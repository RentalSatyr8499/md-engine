* A process’s memory is divided into conceptual regions such as code, writable data, heap, and stack. The operating system reserves part of the address space for {{itself (the kernel)}}, typically at high addresses.
    * The stack grows in what direction? {{Downward from high virtual addresses}}. 
    * The heap grows in what direction? {{Upward from lower addresses}}.
    * The code and constant data live at the {{lowest}} virtual addresses.
* Each process believes that it owns {{a full, private address space}} starting at address {{0}}.
    * In reality, {{multiple processes share the same physical memory}}. The OS creates a mapping from each process’s virtual addresses to physical memory locations.
    * During a {{context switch}}, the OS swaps which mapping is active, giving each process its own “view” of memory.
    * Some regions are marked as accessible only in kernel mode.
* Every time the program accesses memory, it uses a virtual address generated by the CPU. The OS and hardware translate this into a physical address before accessing RAM.
    * The virtual address space is divided into fixed-size blocks called pages. Because page sizes are always {{powers of two}}, the upper bits of an address form the {{"virtual page number" (VPN)}}, and the lower bits form {{the page offset}}. 
    * Each virtual page is conceptually assigned to a region (ex. {{code, data/heap, stack, or unused}}).
    * T/F: Virtual and physical address spaces can be different sizes. {{`T`}}
    * T/F: Virtual pages must always appear in the same order in physical memory as they do in virtual memory. {{`F`}}
    * T/F: At any given point in time, every virtual pages is mapped (has been assigned a physical page). {{`F`}}
* A page table maps {{virtual page numbers (VPNs)}} to {{physical page numbers (PPNs)}}. Each entry usually contains (1) {{the valid bit (indicates whether the virtual page is currently mapped)}}, (2) {{the PPN if valid}}, and (3) {{permission bits}}.
    * The CPU uses the {{VPN}} to index into the page table.
    * If the valid bit is 0, {{the CPU raises a page fault}}.
* Pointers and VA sizes: 
    * T/F: pointer sizes can be larger than virtual address sizes. {{`T`}} 
    * T/F: virtual address sizes can be larger than pointer sizes. {{`F`}} 
    * If the pointer size is larger than the virtual address's size, then the rest of the bits {{just have a fixed value}}.
* If the physical addresses use less bits than the virtual addresses do, some virtual addresses simply remain unmapped.
* "Allocate-on-write": on program start up, {{zero stack pages are mapped to physical pages}}.
    * If it runs into an instruction that requests stack space that is currently unmapped, then {{exception is triggered}}.
    * In the exception handler, the OS {{allocates more stack space and updates the page table. Then the instruction is retried}}. 
* "Copy-on-write": when duplicate processes run, the OS shares as much data between them for as long as possible. 
    * {{Read-only}} pages are always shared between duplicate processes .
    * Writable pages will be shared between duplicate pages until {{one process modifies the data}}. 
        * Before any modifications, these pages are marked {{read-only}} in the page table so that writing to them causes {{an exception to be raised}}. 
        * Important! The process that didn't write to the data stays associated with the read-only page.
* `mmap` creates a virtual memory region whose contents come from {{a file}}. The return value, `data`, is a pointer into your virtual address space.
    * Reading from `data[i]` causes the OS to {{load the corresponding page of the file into memory on demand}}. Writing to `data[i]` modifies the in‑memory page.
    * You can treat the mapped region exactly like an array, but the OS is secretly doing {{page‑fault}}‑driven I/O behind the scenes.
    * Linux models every region of a process’s memory as if {{it were created by `mmap`}}. 
        * When a program is loaded, its code and data come from the {{executable file}}. These pages are initially {{shared and read‑only}}. If the program writes to one of these pages, the OS: {{allocates a new physical page, copies the original contents, and updates the page table entry}}.
        * Other stuff that requires memory but isn't loaded from disk, like the {{stack and heap}}, are allocated a "backing file" that is full of {{zeroes}} on demand. This is called {{anonymous mapping}}.
* `/proc/self/maps` is how Linux tracks {{memory regions}}. The difference between `/proc/self/maps` and page tables is that {{`/proc/self/maps` describes logial regions of memory, so it's for the OS. On the other hand, page tables describe page-by-page mappings, so it's for the hardware}}.

    * If you had a page table with $2^{20}$ entries, the address  `0x12345678` would have a page number of {{`0x12345`}} and a offset of {{`0x678`}}.
